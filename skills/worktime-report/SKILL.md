# 云效工时统计

统计云效（阿里云 DevOps）各项目成员的工时填报情况，生成 Excel 报表和文本摘要。
工时归属日期按北京时间自然日计算（使用记录的 gmtStart 字段，补填历史工时不会算进当天）。
跨多天的整周记录会自动按天均摊到每日统计中。

## 使用前提

运行前必须确认本技能目录下 `codeup-tools/.env` 已正确配置（对照 `.env.example`）。必填三项：

- `YUNXIAO_TOKEN`：云效个人访问令牌（云效工作台 → 个人设置 → 个人访问令牌，需勾选"项目协作"权限）
- `YUNXIAO_ORGANIZATION_ID`：组织 ID（组织管理后台 → 基本信息）
- `YUNXIAO_DOMAIN`：接入点域名，标准版为 `openapi-rdc.aliyuncs.com`，一般无需修改

若发现 `.env` 中仍是占位符（`pt-your_token_here` 等），向用户索要以上配置并写入 `.env`。
**注意：不要把 token 明文回显到对话里。**

## 统计命令

在本技能目录的 `codeup-tools/` 子目录下执行：

```bash
node worktime-report/index.js                        # 统计今天（单日模式）
node worktime-report/index.js 2026-08-29             # 统计指定日期
node worktime-report/index.js 2026-08-01 2026-08-31  # 统计日期区间（多 Sheet 报表）
```

- 单日模式：Excel（工时汇总 + 工时明细）+ 日报文本
- 区间模式：一个 Excel 文件含 3 个 Sheet——`汇总`（每人总工时/条目/状态）、`每日统计`（姓名×日期矩阵，含按日合计）、`工时明细`（归属日期/项目/工作项/描述/录入时间）

## 执行规则（必须遵守）

- 统计脚本必须**前台同步执行**：发出命令后一直等到命令结束返回，再进行下一步。
- **严禁后台运行**（`nohup`、`&`、run_in_background 等一律禁止），
  **严禁**回复"等待/挂起/稍后完成/hold until it completes"之类的话后结束回合——
  你没有真正的等待能力，回合一旦结束，后台任务的结果就永远拿不到了。
- 月度/区间统计较慢（要遍历全部项目和工作项，可能持续数分钟，期间会打印进度），
  这属于正常现象，耐心等命令返回即可。
- 若执行工具超时中断：**重新执行同一条命令**（脚本可重复运行，会重新生成并覆盖报表），
  直到看到最终的汇总输出为止。
- 只有当命令真正返回、终端打印出工时汇总后，才算完成。

## 结果交付

回复按"**先汇总、后明细**"组织，**不要按名单顺序逐人罗列**：

1. **总览**（取终端"统计完成"段）：统计范围、总工时、工时条目数、已填报 x/y 人、未填报名单
2. **按项目汇总**表：项目、工时、占比、条目数（终端已按工时降序输出）
3. **按人员汇总**表：姓名、工时、占比、状态（已按工时降序，与名单顺序无关）
4. **明细不进对话**——逐条记录太多只会刷屏，让用户下载 Excel，
   在"工时明细"Sheet 点击表头筛选按钮，即可按姓名/归属日期/项目筛选

5. Excel 报表用以下命令生成下载链接（`<日期或区间>` 替换为输出文件名中的日期部分；`<SESSION_ID>` 为当前会话 id）：

```bash
bash /home/agentrunner/apps/make-dl-link.sh "worktime-report/codeup-tools/reports/工时报表_<日期或区间>.xlsx" "<SESSION_ID>"
```

把脚本输出的 markdown 链接**原样**放入回复末尾。
**禁止复用历史消息中出现过的链接或 token**——token 有效期极短，旧链接必然失效，每次都必须重新执行脚本。

## 名单说明

统计名单**自动获取**：云效组织级用户接口（个人访问令牌）未开放，
故取 **全部项目成员的并集 ∪ 实际填报过工时的人**（按 userId 去重），
项目里增减成员、有人新填报时自动生效，无需手工维护。
如需排除某些账号（机器人、挂名账号等），把用户名写进 `codeup-tools/data/exclude-names.json`（JSON 数组），缺省或 `[]` 表示不排除任何人。
